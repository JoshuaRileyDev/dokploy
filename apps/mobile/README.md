# Dokploy mobile

An Expo (SDK 58) app for running a Dokploy instance from your phone or iPad.

It is built from native iOS pieces rather than custom chrome. Content is laid
out as inset-grouped lists in system colours (`PlatformColor`), so light mode,
dark mode and Increase Contrast work automatically. Liquid Glass appears only
where iOS 26 puts it: the tab bar (`NativeTabs`), navigation bars and toolbar
menus (`Stack.Toolbar`), sheets, and buttons and segmented controls rendered by
SwiftUI through `@expo/ui`. Long-pressing a service shows a native context menu
with a live preview (`Link.Preview`). Android falls back to plain equivalents.

## What it does

- **Overview**: what's building right now, failing services, recent
  deployments across every project, and each server's disk usage.
- **Projects**: each project and environment, with applications, compose stacks
  and databases (Postgres, MySQL, MariaDB, Mongo, Redis, libSQL).
- **Service**: deploy, redeploy, start and stop, reload, rebuild and cancel a
  build. Shows build logs streamed live over the `/listen-deployment` WebSocket,
  deployment history, runtime logs, domains, and an environment editor with
  values masked.
- **Servers**: disk usage and history, containers (tap one to restart it),
  Docker cleanup, Traefik reload, and running shell commands with their output
  (`serverCommand.*`).
- **Workflows**: repositories, run history, dispatch, and re-running or
  cancelling a run. Shows jobs, steps and logs for each run.
- **Search**: searches services, projects, servers and repositories.

## Connecting

**Sign in with email and password** (the default). The app signs in through
Dokploy's own auth endpoints (`/api/auth/sign-in/email`, then
`/api/auth/two-factor/verify-totp` or `verify-backup-code` when two-factor
authentication is on). It keeps the signed session token in the iOS Keychain or
Android Keystore and sends it on every REST and WebSocket request as both
`Authorization: Bearer <token>` and the session cookie. The bearer header needs
the server's `bearer()` better-auth plugin; servers without it still accept the
cookie. You act as your own user, in your active organization, with your role's
permissions. You can switch organization in Settings. A rejected session (expired
or revoked) returns you to sign-in. Signing out ends the session on the server.

**API key**: choose *Use an API Key Instead*, then enter a key from Dokploy
(Settings → Profile → API keys). It is sent as `x-api-key`. A key belongs to one
organization.

**Explore the demo** runs the whole app against an in-memory mock of the
Dokploy API (`src/lib/mock.ts`), with no network access. Actions mutate the mock
state, so a demo deploy streams a build log and then finishes.

## Development

This app installs its own `node_modules` rather than joining the repo's pnpm
workspace (see `.npmrc`), and `.env` sets `EXPO_NO_METRO_WORKSPACE_ROOT=1` so
Metro serves from this folder. Install packages with
`npx expo install <pkg> -- --ignore-workspace`; plain `pnpm add` rewrites the
repo's root lockfile.

```sh
cd apps/mobile
pnpm install --ignore-workspace
pnpm ios         # builds a dev client into the iOS simulator (needs Xcode 26+)
pnpm start       # Metro only, once the dev client is installed
pnpm typecheck
```

`ios/` and `android/` are generated by `expo prebuild` and are git-ignored.
Configure native settings in `app.json`.

## Layout

```
src/app/                    routes (expo-router)
  (tabs)/_layout.tsx        NativeTabs: Overview, Projects, Servers, Workflows, Search
  (tabs)/(home,…,search)/   one native stack shared by every tab
  deployment/[id].tsx       live build log sheet
  command/[serverId].tsx    run-a-command sheet
  connect.tsx, settings.tsx
src/components/             list rows and sections, native controls, log view
src/lib/                    API transport, demo backend, session, query hooks
src/theme/                  palette, status tones, responsive breakpoints
```
